# 编写任务型技能

参考 [技能编写规范](references/authoring-standard.md)，根据任务复杂度选择所需内容。

## 明确用途

从用户已有说明确定目标、输入、交付物、使用环境与授权范围。
只有缺少的信息会实质改变结果时才提问。不要把单次任务中的偶然偏好提升为普遍规则。
修改已有技能前先阅读入口和实际使用的参考资料，保留仍适用的行为。

## 编写

选择能准确触发任务的名称和描述。入口写清决策依据、必要流程、权限边界与完成条件。
按需添加 references、scripts 或 assets；短技能可只有 SKILL.md。
脚本只用于值得复用或需要确定性的操作。参考资料放在技能目录内并从入口链接。
不要求固定章节数、步骤数或无意义的配套文件。

## 验证与交付

检查元数据、目录名、相对链接、资源可用性和未替换占位符。
用一个典型请求检查流程能否走通，并考虑一个不应触发的相邻请求。
有脚本时运行与风险相称的代表性验证；有现成校验器时可以使用，但格式通过不等于行为正确。
交付时说明技能位置、适用范围、验证结果与限制。
创建或修改技能不自动授权安装、发布、发送消息或执行技能中描述的外部操作。
