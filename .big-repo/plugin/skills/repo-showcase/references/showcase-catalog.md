# 六类仓库玩法目录

这些是可选展示能力，六类检查固定存在，不要求每个项目安装全部功能。先确认实际资料、公开性和维护预算。

| 类别 | 用途与真实工具案例 | 接入、依赖和权限 | 成本与适用性 | 失效与移除 |
| --- | --- | --- | --- | --- |
| 增长与活动 | [Star History](https://github.com/star-history/star-history) 提供星标历史嵌入；本地发布记录可生成版本时间线 | 公开仓库按服务文档生成 SVG 链接，并保留文字入口；只读公开数据，无须把令牌写进 README | 第三方可用性与数据覆盖需要复查；适合公开项目，Star 不等于使用人数 | 图表失败时保留文字链接或移除托管区；私有仓库不调用公开服务 |
| 状态徽章 | [Shields](https://github.com/badges/shields)；GitHub 原生工作流状态徽章 | 选择真实工作流、分支、包名与许可证；外部徽章使用公开数据，私有项目优先静态本地 SVG | 少量与读者决策有关的徽章即可，分支或包迁移时更新 | 删除失效徽章，保留真实状态文字；不可写假覆盖率或假成功 |
| 项目门面 | [asciinema](https://github.com/asciinema/asciinema) 终端演示；本地截图、GIF、README 导航与 picture 主题切换 | 自行录制或使用有许可素材；检查账号、密钥、私人路径与画面内容；大媒体按项目规则保存 | UI、CLI 项目更有价值；界面变化后需重录，控制大小并提供替代文本 | 保留文字说明；删除引用及无调用素材，不误删其他页面仍在使用的资源 |
| 快速体验 | [StackBlitz WebContainers](https://github.com/stackblitz/webcontainer-core)、Codespaces、现有示例和 Playground | 只链接已核实的公开体验；环境创建可能需要账号、费用或网络。新建部署和一键执行入口需明确授权 | 适配技术栈；CLI、系统组件优先使用可复现本地示例 | 失效时回退到本地运行步骤；移除按钮、环境配置及相关服务时单独确认权限 |
| 社区参与 | [All Contributors](https://github.com/all-contributors/allcontributors.org)、真实贡献指南、good first issue 和讨论入口 | 可用静态名单或手工入口；安装机器人和授权仓库写入是独立动作，不因生成名单自动执行 | 贡献类型应包含真实文档与支持工作；定期检查名单、许可及链接 | 保留致谢文字；移除生成区或配置，卸载机器人不由普通文档任务代办 |
| 项目故事 | 从真实 Release、里程碑、CHANGELOG 提炼亮点和时间线；彩蛋只在明确需要时加入 | 读取实际提交与发布记录；版本草稿必须标草稿，不声称已经发布 | 不依赖第三方统计服务，适合有演进记录的项目；每次版本准备时核对 | 归档旧时间线或删托管区；无记录时只写愿景与路线图，并清楚标注 |

## 模板与验收

完整插件 templates/showcase.md 提供六类草稿；使用时只保留已核实入口。scripts/repo_tools.py preview 仅生成导航和明确选择的公开 Star History，其他内容由技能按真实资料组装。

采用 `<!-- big-repo:showcase:start -->` 与 `<!-- big-repo:showcase:end -->` 标记生成区。重复生成不得复制整个区块；未标记内容只按明确任务修改。

没有 Star 历史就不生成增长结论；零 Star 可以不展示图表；没有发布就不添加发布成功徽章。数据缺失、远程未检查、服务限流与采样范围均需在交付说明中标注。

离线检查只验证可识别 Markdown/HTML 引用、文件存在性、占位符和私有外部媒体，不覆盖全部 Markdown 扩展语法。远程链接由用户授权的网络工具人工检查，禁止把私有标识发到公开统计服务。

定时生成 SVG 的工作流、部署与机器人只提供按需草稿；不默认安装。删除整个托管区即可撤销本地展示；外部服务和机器人配置需要单独处理，不能把删 README 等同于撤销权限。
