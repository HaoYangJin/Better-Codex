# 变更记录

## 2.1.0

- 新接入默认本地提交、core 资源、无客户端常驻入口与展示；create/init 支持 dry-run 预览。
- schema 2 记录显式策略；旧配置先确认再开始任务与远端交付，本仓库继续保留明确授权的 merge。
- 新增 upgrade/disconnect、运行目录暂存替换与备份、中断恢复及冲突保护；解除接入保留 README、运行目录与任务历史。
- core 来源不能虚报 full 升级成功；待恢复生命周期阻止新任务和接入写入。
- 旧命名空间迁移前须完成或显式取消活动任务，保留闭合任务身份与证据；迁移说明与资源链接使用当前策略和版本。
- 补充 MIT 许可证、行为准则与基于实际发行记录的项目故事，更新接入、迁移和社区导航。

兼容性变化：2.0 的 merge、双客户端入口和展示默认不再用于新接入；已有策略不会静默升级。2.1 发布状态以 Releases 为准。

## 2.0.0

- 全面更名为 Big-Repo，运行与配置 ID 改为 big-repo；目录扁平化，集中 8 个技能与 6 个模板。
- 新增显式旧配置迁移、新仓库创建、已有仓库展示补齐与幂等同步。
- 扩展离线探索台：能力地图、模板工作台、交付挑战及真实版本时间线。
- 提供中英文 README、浅色抽象品牌社交图片和真实状态及 Star History 入口。
- 打包与接入共用运行资源白名单；旧配置和任务需显式迁移并重新验证与独立审查。

BREAKING CHANGE: 插件 ID、市场 ID、运行路径及 GitHub 仓库名称发生变化。迁移见 docs/migration.md；不静默替换全局客户端安装。

## 1.3.0

- 插件显示名、ZIP 文件名与顶层目录统一为 Repo-Standards；保留 repo-maintainer 内部 ID、技能与配置路径，附完整升级和回退说明。
- 新增零前端依赖、零网络请求的离线探索台：本地 Git 结构快照、Markdown 导出、四种交付演练和六类玩法筛选；模拟状态与实际交付证据明确分离。
- 首页恢复流程可视化、可运行体验与参与入口；用本仓库实际检查整理展示文档、目标对照和验收记录。
- 修复 GitHub 仓库名大小写差异导致 begin / deliver 误判仓库已更换的问题，仍阻止切换到不同仓库。
- 打包包含离线页面资源，发布流程兼容历史制品名称并验证新品牌制品。

## 1.2.0

- 收敛为配置一次、由开发需求和反馈触发的项目维护与自动交付工具；普通问答和只读请求按原范围执行，不添加定时巡检。
- 新增项目接入，保存项目策略、可移植运行目录以及 Codex AGENTS.md / Claude Code CLAUDE.md 入口，保留已有项目说明。
- 新增任务、实际验证、独立审查登记、自动推送/PR/合并及中断恢复入口，状态留在 Git 元数据中，复用事件和已有远端交付。
- 已核实无远端 CI 的项目可显式配置 ci_policy=none；本地验证、独立审查和其他可见检查仍需通过。
- 重写首页与使用说明，把研究、展示和自身发行资料放到辅助入口；已发布 1.1.0 保持不变。

## 1.1.0

- 维护默认改为范围内自动诊断修复、重新验证、独立 AI 审查及复审，CI 成功后自动合并；外部权限、网络或范围外决策才交接。
- 新增 `repo_tools.py merge`：重新运行全部合并门槛，锁定最终 head SHA 执行一次 squash 合并，查询远端 MERGED 与合并提交后才返回成功；等待、失败、队列与不确定写入均不误报完成。
- 修复 PR 查询对 GitHub CLI 2.46 的兼容性：移除未被使用且该版本不支持的 `baseRefOid` 字段，保留提交、目标分支与合并结果核对。
- 统一六项技能的任务协议、研究建议说明、任务和交接模板，明确历史失败日志与当前候选证据的区别。
- 指定版本发布可复用同一委托中的明确授权；默认仍只准备材料，不部署、不配置常驻自动化或全局插件。
- 更新双平台插件清单、市场版本、下载与升级入口，补充合并工具的隔离回归验证。

兼容旧的任务与证据格式，新增合并命令会写远端。行为迁移：旧版首次失败停止改为自动修复；需要旧策略的任务可明确声明首次失败交接。历史客户端加载证据不代表本版已完成加载或模型端到端验证。

## 1.0.0

首次 GitHub 发行的版本内容，整合此前未发布到 Releases 的 0.1.0 与 0.2.0 源码成果。

- 六项共享技能：仓库接管、维护交付、仓库审查、发布准备、技能维护与仓库展示。
- 基于 60 个官方或组织仓库的分类研究，插件内置精简结论与可追溯来源，完整档案保留在源仓库。
- 只读预检、验收、合并门槛及展示检查；验证、独立审查与 CI 全部通过后默认自动合并，首次非预期失败交接。
- 六类固定仓库玩法，支持按项目筛选；私有仓库不向公开图表服务发送标识，不编造趋势。
- 修复打包临时文件名冲突、中断残留及校验和输出跟随符号链接；保留确定性 ZIP 与 SHA-256。
- 增加版本化下载入口和安装、校验、升级及回退说明。

与 0.2.0 的技能调用及工具命令兼容，无任务模板迁移要求。Python 工具要求 Python 3.11+、Git；GitHub 查询与采集还需已登录的 gh。未引入常驻服务、全局自动安装或部署。

Codex 已完成隔离安装、六技能发现，并在用户另行授权本机安装后用真实模型执行 repo-showcase 离线审查；Claude Code 已完成清单校验、实际加载和六技能清点，模型任务尚未验证。没有将这一冒烟场景扩大为六技能全部端到端通过。正式发布仅在用户明确授权的独立发布任务内执行；技能默认仍只准备发布材料。
