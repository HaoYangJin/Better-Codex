# 技能编写规范

格式依据：[Agent Skills specification](https://agentskills.io/specification)。以下工作方法是本仓库的编写建议。

## 必需结构

每个技能目录包含 SKILL.md，以 YAML 元数据开头，再写 Markdown 指令。
name 与目录名一致，使用小写字母、数字及单连字符，最长 64 个字符，首尾不使用连字符。
description 非空，最长 1024 个字符，说明用途和触发场景。

```text
example-skill/
  SKILL.md
  references/   按需：详细说明
  scripts/      按需：可执行辅助工具
  assets/       按需：交付物使用的资源
```

## 内容建议

描述应让代理区分相近任务。正文提供会改变操作决策的信息：如何选择路径、输入不足时怎么办、什么结果算完成。
长篇或仅在特定模式下使用的资料放到 references，通过相对链接说明何时读取。
避免重复通用常识，也不把所有任务强制塞进同一流程。

## 权限与可移植性

技能不能替用户授予发布、删除、付费或发送消息的权限。复用已有授权，不对普通可逆步骤反复确认。
不硬编码本机路径、私人账号、密钥或当前会话状态。环境依赖需要清楚说明。
技能目录整体复制后仍应保留所需资源；不要依赖作者机器上的其他技能文件。

## 验收建议

选择一个典型任务检查可执行性，再用一个相邻场景检查触发是否过宽。
核对元数据、链接和资源；正式技能不保留草稿占位符。
脚本需实际运行并检查结果；仅文档修改可进行内容检查。
记录未验证的部分，避免把格式检查当成完整功能验证。
