# 整理与提交 Git 改动

先确认当前仓库的指令和提交约定；没有已有约定时参考 [提交规范](references/commit-conventions.md)。

## 工作方式

1. 检查状态、当前分支、已暂存和未暂存差异，区分本次任务与已有工作。
2. 按任务目标组织改动，保留无关修改。用户只要求写提交信息时，直接提供信息，不暂存或提交。
3. 需要提交时，按文件或补丁暂存；已暂存的无关内容应先说明并澄清处理范围，不擅自取消他人的暂存。
4. 执行与改动匹配的验证，再检查暂存差异和空白错误。
5. 提交信息说明可观察的结果；必要时在正文解释原因、验证与兼容性。
6. 提交后确认提交内容与工作区状态，报告提交标识、摘要和实际验证结果。

## 操作边界

仅在请求包含提交意图时执行 commit。推送、创建 PR 或发布须在任务授权范围内。
不擅自清理工作区、修改全局 Git 配置、重写历史或强制推送。
检查发现凭据时不要把其值复制到日志或回复中，先处理泄露风险再提交。
